# doppler_project_member_service_account_role_assignment (Resource)

Manage a single role assignment for a Doppler project service account member.

**Note:** You can also exclusively manage a member's access to a project with a single role.
See the `doppler_project_member_service_account` resource for more information.

**Note:** Destroying the last role assignment a member holds on a project removes the member from the project.

## Example Usage

```terraform
resource "doppler_project_member_service_account_role_assignment" "backend_ci_viewer" {
  project              = "backend"
  service_account_slug = doppler_service_account.ci.slug
  role                 = "viewer"
  environments         = ["dev", "stg"]
}

resource "doppler_project_member_service_account_role_assignment" "backend_ci_collaborator" {
  project              = "backend"
  service_account_slug = doppler_service_account.ci.slug
  role                 = "collaborator"
  environments         = ["prd"]
}
```

## Schema

### Required

- `project` (String) The name of the Doppler project where the access is applied
- `role` (String) The project role identifier for this assignment. Must use either one of the built-in project role slugs (`admin`, `collaborator`, or `viewer`), or the slug for a custom project role. A member holds each role at most once per project.
- `service_account_slug` (String) The slug of the Doppler service account

### Optional

- `environments` (Set of String) The environments in the project where this role applies (null or omitted for roles with access to all environments)

### Read-Only

- `id` (String) The ID of this resource.
