# doppler_project_member_user_role_assignment (Resource)

Manage a single role assignment for a Doppler project user member. Requires the environment-scoped roles feature.

**Note:** You can also exclusively manage a member's access to a project with a single role.
See the `doppler_project_member_user` resource for more information.

## Example Usage

```terraform
data "doppler_user" "brian" {
  email = "brian@doppler.com"
}

resource "doppler_project_member_user_role_assignment" "backend_brian_viewer" {
  project      = "backend"
  user_slug    = data.doppler_user.brian.slug
  role         = "viewer"
  environments = ["dev", "stg"]
}

resource "doppler_project_member_user_role_assignment" "backend_brian_collaborator" {
  project      = "backend"
  user_slug    = data.doppler_user.brian.slug
  role         = "collaborator"
  environments = ["prd"]
}
```

## Schema

### Required

- `project` (String) The name of the Doppler project where the access is applied
- `role` (String) The project role identifier for this assignment. Must use either one of the built-in project role slugs (`admin`, `collaborator`, `viewer`, or `no_access`), or the slug for a custom project role. A member holds each role at most once per project.
- `user_slug` (String) The slug of the Doppler workplace user

### Optional

- `environments` (Set of String) The environments in the project where this role applies (null or omitted for roles with access to all environments)

### Read-Only

- `id` (String) The ID of this resource.
