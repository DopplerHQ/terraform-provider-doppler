# doppler_secret (Resource)

Manage a single Doppler secret in a config.

## Example Usage

```terraform
resource "random_password" "db_password" {
  length = 32
  special = true
}

resource "doppler_secret" "db_password" {
  project = "backend"
  config = "dev"
  name = "DB_PASSWORD"
  value = random_password.db_password.result
}

output "resource_value" {
  # Access the secret value
  # nonsensitive used for demo purposes only
  value = nonsensitive(doppler_secret.db_password.value)
}
```

### Keeping the value out of Terraform state

`value` is stored in the Terraform plan and state, in plain text. With Terraform 1.11 or later, set
`value_wo` instead: it is a [write-only argument](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments),
so Terraform passes it to Doppler but never stores it. Pair it with an ephemeral source, such as an
`ephemeral` resource or a variable declared with `ephemeral = true`, so the value is not stored anywhere else either.

Because Terraform does not store `value_wo`, it cannot tell when the value changes. Increment
`value_wo_version` whenever you want to write a new value to Doppler. Changes made to the value
outside Terraform are not detected, and `computed` is not set.

```terraform
# Requires Terraform 1.11 or later.
ephemeral "random_password" "db_password" {
  length  = 32
  special = true
}

resource "doppler_secret" "db_password" {
  project = "backend"
  config  = "dev"
  name    = "DB_PASSWORD"

  # Never stored in the Terraform plan or state.
  value_wo = ephemeral.random_password.db_password.result
  # Increment to write a new value to Doppler.
  value_wo_version = 1
}
```

## Schema

### Required

- `config` (String) The name of the Doppler config
- `name` (String) The name of the Doppler secret
- `project` (String) The name of the Doppler project

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `value` (String, Sensitive) The raw secret value. This value is stored in the Terraform state. Exactly one of `value` or `value_wo` must be set.
- `value_type` (String) The value type of the secret
- `value_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The raw secret value, as a write-only argument that is never stored in the Terraform plan or state. Terraform cannot detect changes to it, so change `value_wo_version` to write a new value. Exactly one of `value` or `value_wo` must be set.
- `value_wo_version` (Number) A version number for `value_wo`. Change it to write a new `value_wo` to Doppler. Must be 1 or greater. Required when `value_wo` is set.
- `visibility` (String) The visibility of the secret. One of `masked`, `unmasked`, or `restricted`. Defaults to `masked`.

### Read-Only

- `computed` (String, Sensitive) The computed secret value, after resolving secret references. Not set when `value_wo` is used, so that the value is kept out of the Terraform state.
- `id` (String) The ID of this resource.

## Import

Import is supported using the following syntax:

```shell
terraform import doppler_secret.default <project-name>.<config-name>.<secret-name>
```

Import reads the current value into `value` and `computed`. If the resource uses `value_wo`, those
are removed from state by the first apply after the import.
